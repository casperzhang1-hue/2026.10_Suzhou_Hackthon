## 四、我在这一轮改了什么（5 项，都有测试锁）

合并不是把文件搬过来，**合并会暴露原来两边各自藏着的问题**。这五项都是实测撞出来的：

| # | 问题 | 症状（可复现） | 改法 |
|---|---|---|---|
| 1 | **缺口把「没学」算成「完成」** | seed 里 10-27/10-29 时长 0，旧口径 `week_done=5`、`owed=0` → 演示里那句「本周欠 2 次」当场消失 | 只数时长 > 0 的天，`owed=2` 回来 |
| 2 | **今天没学时按 0 分结算** | 每天 0 点就把今天记成完成度 0，早上打开就是「蔫了 30」 | 今天没记录就只结算到昨天；新增 `pending_today` |
| 3 | **A 的 seed 格式 B 读不了** | A 用 `days[]`，B 只认 `records[]` → 直接拷过去 B 读空库，今日屏变「休眠 / 欠 5 次」 | 写 `D-module-materials/tools/seed_to_backend.py`，转换后 44 条记录 + 3 条记忆 |
| 4 | **前后端两套算法** | 同一 seed：A mock 说 steady/64，B 后端说 wilt/40 | B 的信号层按 A 重写（completion=时长/80、energy=100−时长/6−熬夜30、progress=正确率×100、起点 30），并加 `test_parity_a.py` 锁死 |
| 5 | **`.gitignore` 那条根本不生效** | `mock-server/data/records.json` 匹配不到 `A-module-frontend/mock-server/data/records.json`，运行时数据一直被 `??` 盯着 | 改成 `**/mock-server/data/records.json` |

顺带修掉的：B 现在会从 `modules` 反算正确率（原来确认卡传 `accuracy:null` 就永远是空，P0-4 只解了一半，现在解全了）；`/api/today` 补了 `detail` 字段，和 A mock 同结构。

## 六、两个必须现在拍死的判断

### 判断 1：演示资产定为「原型单文件」，工程只做架构展示

`A-module-frontend/原型/仓鼠陪跑_原型_接真数据_单文件版.html` 是**唯一四屏齐全**（今日 / 记忆 / 档案 / 出分日）、**自包含**（识别模块已内联、图片 base64）、**渲染已验证**的资产。Vue 工程缺两屏、没接过 `/api/today`、从没 build 过——**三个理由，都是现场翻车的理由**。

话术提前想好：**"工程在后端接了完整接口和 36 个测试，演示用单文件版是为了追求投屏稳定。"** 这句比现场蓝屏强一百倍。

### 判断 2：B 的价值不在"跑"，在"证明"

B 现在能给出的是别的东西：**29+7 个测试、golden 对拍、字段校验、原子写盘、`HAMSTER_TODAY` 可回放**。这些回答的是评委那句"你这东西是不是写死的"。

所以 B 的用法是：**PPT 里一页、问到就打开 `/docs`（FastAPI 自带 Swagger）指一下接口**，而不是现场 `uvicorn` 起来打开浏览器。
