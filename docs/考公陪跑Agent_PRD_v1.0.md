## 一、背景与目标

### 1.1 背景

产品不做内容供给，只做一件事：**在备考 180 天里，每天知道用户是什么状态，并且在该让他停的时候让他停。**

### 1.2 要解决的问题

| 现状       | 痛点                |
| -------- | ----------------- |
| 自主填报学习数据 | 数据不准不可信，个性化全失真    |
| 打卡督学     | 互相表演，制造焦虑         |
| 情绪支持     | 只有「加油」式安慰，没有「被看见」 |

### 1.3 成功指标与口径

| 指标      | 目标    | 口径                            |
| ------- | ----- | ----------------------------- |
| 判定一致率   | ≥ 70% | 系统状态判定与用户每日自评的一致比例；低于此值产品不成立  |
| 截图通道渗透率 | ≥ 60% | 活跃日中通过截图上传录入数据的天数占比           |
| 确认卡修正率  | ≤ 15% | 识别确认卡上被用户修改的字段数 ÷ 展示字段总数      |
| 干预采纳率   | ≥ 40% | 用户按建议执行（停止学习/调整计划）的次数 ÷ 干预总次数 |
| D30 留存  | ≥ 45% | 次日留存的用户中第 30 天仍活跃的比例          |
| 周报分享率   | ≥ 15% | 打开周报的用户中分享的比例                 |

> 以上为产品目标值（估算，上线后校准）；**24h 冲刺的验收口径见 13.1，与上表不同**。

## 二、名词与术语

| 术语           | 定义                                      |
| ------------ | --------------------------------------- |
| 陪跑           | 本产品形态：不做内容供给，只做状态推断与陪伴干预                |
| 活力值 vitality | 宠物的生命值，0–100，非对称累积（恶化慢 0.25 / 回暖快 0.40） |
| 羁绊值 bond     | 只涨不跌的关系值，解锁帽子/围巾等装饰，断签不收回               |
| 识别确认卡        | 截图识别后将结果展示给用户、允许修改一次再入库的卡片              |

| 用户四态         | 稳 / 平台期 / 过载 / 崩溃前兆（能量轴 × 进展轴）          |
| 宠物五态         | 元气 / 踏实 / 疲惫 / 蔫了 / 休眠                  |
| seed 数据      | 预置的 30 天虚拟用户历史数据，用于演示记忆能力               |

## 四、方案对比与选型

### 4.1 数据录入通道

| 方案                       | 数据可信度         | 用户摩擦           | 开发成本    | 结论                   |
| ------------------------ | ------------- | -------------- | ------- | -------------------- |
| A. 截图上传为主（多模态一次识别）+ 填报兜底 | 高（带时间戳难伪造）    | 低（学习博主本就有截图习惯） | 中       | **✅ 推荐**             |
| B. 自主填报（chips + 滑杆）为主    | 低（可虚报，宠物状态失真） | 低              | 低       | 降级为兜底（FR-14）         |
| C. OCR + LLM 两段管线        | 中高            | 中              | 高（两套维护） | ❌ 24h 内不可行，长期成本考量再评估 |

### 4.2 宠物形象实现（本次形象变更触发的重新选型）

> **变更背景**：需求方提供仓鼠形象参考图（AI 生成，含正面/侧面/背面三视图：米色仓鼠、米色毛线帽、砖红色围巾、棕色背景）。原「小芽 SVG 连续插值」方案与照片级形象冲突，重新比选：

| 方案                                             | 质感  | 与参考形象一致性  | 开发量 | 24h 可行性 | 结论           |
| ---------------------------------------------- | --- | --------- | --- | ------- | ------------ |
| A. **五态静态图组（AI 生成，风格锁定）+ CSS 微动效**（呼吸/眨眼/耳朵抖动） | 照片级 | 高（以参考图为锚） | 小   | ✅       | **✅ 推荐（本期）** |
| B. 矢量化仓鼠 + 参数连续插值                              | 中   | 低（会偏离参考图） | 大   | ❌       | 后续版本评估       |
| C. 骨骼动画（Lottie/Rive）                           | 最佳  | 中         | 很大  | ❌       | ❌ 拒绝         |

**A 方案下「一致性感知」的实现方式调整**：

- 原「连续插值」验收改为：**五态图差异必须肉眼可辨**（姿态/帽饰位置/眼睛/颊囊/背景道具）+ 每态配 1–2 个 CSS 微动效 + 话术配合
- 三视图的用法：正面 = 主界面默认；侧面 = 页面转场过场；背面 = 周报/出分日等「它先转身」的叙事页
- **毛线帽与围巾 = 羁绊值的可视化载体**：bond 里程碑解锁新帽子颜色/围巾花纹（只涨不跌，断签不收回）——原小芽方案的「解锁小物件」机制平移过来，语义更自然

**仓鼠隐喻体系（替代原植物隐喻，写入表达系统）**：

| 原隐喻（小芽）      | 新隐喻（仓鼠）                                       | 对应机制   |
| ------------ | --------------------------------------------- | ------ |
| 浇水过多烂根 → 疲惫态 | **颊囊塞满**：学太猛，颊囊鼓鼓、帽子歪掉、脚下散落瓜子壳（塞了一堆没消化） → 疲惫态 | 「敢让你停」 |
| 向光生长 → 元气态   | 挺直坐、帽檐端正、眼神亮、颊囊微鼓                             | 元气态    |
| 叶片下垂 → 蔫了态   | 缩成一团、围巾裹紧、耳朵耷拉                                | 蔫了态    |
| 种子休眠         | 蜷成毛球，只露出帽子尖                                   | 休眠态    |
| 年轮/枝干 = 成长记录 | **囤积 = 记忆**：它替你囤着每一天（对账时「翻出来给你看」）             | 记忆屏叙事  |

> 仓鼠是夜行动物——「你凌晨还在学，它也醒着陪你」，与目标用户（在职备考、深夜学习）天然契合，此点写入文案人格设定。

## 六、功能需求

> 编号 FR-xx；验收标准 Given/When/Then；「必须」= shall，本期范围。

### FR-01 截图上传（必须）

- 描述：用户在 H5 页点击「贴一张今天的学习截图」，从相册选择或拍照上传一张图片。
- 规则：仅支持单张；JPG/PNG；≤10MB；上传中显示进度态。
- 验收：
  - Given 用户在首页，When 点击上传并选择一张截图，Then 2 秒内进入识别等待态（不白屏，仓鼠眨眼动效）。
  - Given 用户取消选择，When 返回，Then 停留在首页，无异常提示。

### FR-02 截图识别（必须 · AI 能力）

- 描述：多模态模型一次调用，图片 → 结构化 JSON。禁止 OCR + 二次抽取两段管线。
- 输出契约（必填字段）：

```json
{
  "app": "粉笔 | 番茄ToDo | 其他",
  "date": "YYYY-MM-DD",
  "module": "言语 | 资料分析 | 判断推理 | 常识 | 申论 | 未知",
  "questions": 0,
  "correct": 0,
  "minutes": 0,
  "confidence": 0.0-1.0
}
```

- 规则：`correct ≤ questions`，超出时置信度降级；识别失败不得抛错给用户（走 FR-14 降级）。
- 验收：
  - Given 6 张真实截图测试集，When 批量识别，Then ≥5 张输出合法 JSON（字段齐全、类型正确）。
  - Given 一张无关图片（如自拍），When 识别，Then 返回 `confidence < 0.5` 且进入降级，不报错。

### FR-03 识别校验（必须）

- 规则四条：① 时间一致性（截图时间与当日偏差 ≤36h）；② 数值合理性（correct ≤ questions，minutes ≤ 600）；③ 感知 hash 去重（同一张图重复上传不重复入库）；④ 模块名归一（别名映射到五个标准模块）。
- 验收：Given 一张 3 天前的旧截图，When 上传，Then 确认卡顶部出现「这是 X 天前的记录，确认记到今天吗」的提示，默认记到截图当日。

### FR-04 识别确认卡（必须）

- 描述：识别结果以 4 个可编辑字段展示（模块/题量/正确数/时长），用户确认或修改一次后入库。
- 验收：
  - Given 识别结果展示，When 用户修改任一字段并点「没问题」，Then 以修改后的值入库，且该字段标记 `edited=true`（用于确认卡修正率统计）。
  - Given 连续 5 次零修正，When 再次识别，Then 提供「自动确认」开关（可以，非必须实现，演示版允许跳过）。

### FR-05 完成度计算（必须）

- 规则：`completion = 0.6 × min(minutes/目标时长, 1.2) + 0.4 × min(题量达成率, 1.2)`
- 防伪锚：填报/识别时长与被动在线时长冲突时取保守值 `min(识别值, 在线分钟 × 1.2)`；不提示、不戳穿。

### FR-06 用户状态判定（必须）

- 双轴四象限，能量轴（作息规律性/深夜占比/情绪）× 进展轴（正确率趋势/连续错题）。

| 精力 | 进展 | 判定     | 干预动作                    |
| -- | -- | ------ | ----------------------- |
| 高  | 高  | 稳      | 不打扰                     |
| 高  | 低  | 平台期    | 建议换方法                   |
| 低  | 高  | **过载** | **「今天别学了，去睡」**（核心差异化判定） |
| 低  | 低  | 崩溃前兆   | 只安抚，不布置任务               |

- 验收：Given 精力低+进展高的信号组合，When 计算，Then 判定「过载」且触发劝停话术（FR-09）。

### FR-07 活力值更新（必须 · 不可更改方向的算法）

```
completion < 0.5 :  vitality = 0.75 × vitality + 0.25 × completion×100   （恶化慢）
completion ≥ 0.5 :  vitality = 0.60 × vitality + 0.40 × completion×100   （回暖快）
```

- 规则：休眠态（断签 ≥7 天）vitality 冻结在 25 不再下跌；bond 只涨不跌。
- 验收：
  - Given vitality=80、断签一天（completion=0），When 更新，Then vitality=60（只掉 25%，宠物「有点蔫」而非崩溃）。
  - Given vitality=60、completion=1.0 回归日，When 更新，Then vitality=76（立刻回暖 40%）。

### FR-08 宠物形态展示（必须 · 形象变更后重写）

- 五态映射：元气 ≥78 / 踏实 55–78 / 疲惫（过载判定日）/ 蔫了 30–55 / 休眠（断签 ≥7 天）。
- 资产规格（交付物）：

| 态  | 视觉要点                      | 微动效        |
| -- | ------------------------- | ---------- |
| 元气 | 帽檐端正、眼神亮、颊囊微鼓、光点          | 呼吸起伏 2s 循环 |
| 踏实 | 标准坐姿                      | 呼吸起伏       |
| 疲惫 | **颊囊鼓胀、帽子女歪、脚下瓜子壳散落、眼半闭** | 慢速眨眼       |
| 蔫了 | 缩团、围巾裹紧、耳朵耷拉              | 偶尔耳朵抖      |
| 休眠 | 蜷成毛球、露帽尖                  | 无（静止即表达）   |

- 验收：
  - Given 五态图，When 依次切换，Then 每两态之间差异**肉眼立辨**（不做连续插值，以差异辨识度替代）。
  - Given 参考图三视图，When 出场/转场/周报，Then 分别使用正面/侧面/背面。

### FR-09 表达系统（必须）

- 12 条模板话术（四态 × 3），铁律：主语必须是「我」（"我今天没什么精神"）；禁用词库（加油/你一定行/坚持就是胜利/别放弃）；能给数字就给数字。
- 输出后校验：含禁用词或主语为「你」的句子不展示，取下一条模板。
- 验收：Given 任一态触发，When 输出话术，Then 通过禁用词与主语双重校验。

### FR-10 记忆屏（必须，seed 驱动）

- 展示 3 条历史引用，其中 ≥1 条为冲突对账：「你 41 天前说资料分析一定能拿下。这周它是 48%。你当时少算了什么？」
- 数据源：seed 数据（FR 依赖 D 交付 `seed.json`，B 灌库）。
- 验收：Given seed 已灌库，When 打开记忆屏，Then 3 条引用的时间/内容/数字与 seed 完全一致（**自洽是硬验收**）。

### FR-11 出分日屏（必须）

- 首字是「我在」，不出现分数；背景使用仓鼠背面视图（「它先转身等你」）。

### FR-12 降级链（必须）

截图识别失败 → chips 选项兜底（模块多选 + 题量四档 + 感受三档）→ 仍无数据 → 仅用被动信号计算，置信度标记低。**任何一步不得卡死用户。**

### FR-13 周报（可以，本期仅在 16:00 后有余力实现）

### FR-14 埋点（必须，最小集）

| 事件                      | 触发            | 字段                           |
| ----------------------- | ------------- | ---------------------------- |
| s1_upload               | 上传完成          | file_size, ocr_ok            |
| s2_confirm              | 确认卡提交         | edited_fields[], duration_ms |
| s4_active/passive       | onShow/onHide | ts（服务端时间）                    |
| s5_intervention_outcome | 干预后回访         | adopted, ignored, offended   |

## 八、业务流程与状态流转

### 8.1 主流程（五步动线）

```
上传截图 → [识别] → 确认卡 → [入库+计算] → 宠物形态+话术 → 记忆屏 → 出分日屏
              ↓失败                    ↓
           chips 兜底(FR-12)        正常展示
```

### 8.2 宠物状态机

| 当前态   | 触发事件              | 迁移到                   |
| ----- | ----------------- | --------------------- |
| 任意    | 断签 ≥7 天           | 休眠（vitality 冻结 25）    |
| 休眠    | 用户回归当日任意录入        | 蔫了（首句「你回来了」，绝口不提离开多久） |
| 踏实    | completion<0.5 累积 | 蔫了（vitality 跌破 55）    |
| 踏实/元气 | 过载判定              | **疲惫**（不是开心，是劝停）      |
| 蔫了    | completion≥0.5    | 踏实（vitality 回涨 40%）   |
| 任意    | vitality ≥78 且无过载 | 元气                    |

> ⚠️ 用户四态与宠物五态**不是一对一映射**：用户今天「过载」但宠物可能还在「踏实」（历史活力未耗尽）。错位是设计（缓冲垫），禁止实现成严格镜像。

## 十五、附录

### 15.1 AI 功能专项契约（精要）

- **任务定义**：多模态模型在用户上传学习截图时，完成字段结构化抽取（草稿级，经确认卡人工确认后生效）；当前主要成本 ≈¥0.005/次。
- **输入契约**：单张截图；缺字段时输出 `confidence<0.5` 而非编造；实时（截图时间）与历史冲突时以截图时间为准。


- **输出契约**：FR-02 JSON Schema，必填字段缺失即视为失败；禁止输出自然语言描述替代结构化字段。
- **质量标准**：6 张测试集 ≥5 张合法 JSON；字段级验收样本含 常规/无关图/旧图/数值颠倒 四类。
- **异常降级**：失败不弹错，降级 chips（见 FR-12）；人工接管点 = 确认卡（ Always do：结构化抽取；Ask first：入库；Never do：无可靠来源时编造字段、修改用户未确认的数据）。
- **反馈闭环**：`edited_fields` 逐字段记录，用于确认卡修正率与 prompt 迭代。
