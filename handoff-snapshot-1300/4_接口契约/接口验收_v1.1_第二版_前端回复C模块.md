### 对两处改动的评价

**超时放宽 + 取消重试**：认同。10 秒窗口把正常模考报告图误杀成"非学习图片"是硬伤，而"偶发慢响应"重试大概率仍然超时，还会把最坏耗时翻倍。20 秒单次窗口 + 不重试，最坏耗时可预期（20s），比原来的 10+10=20s 更可控且不牺牲成功率。

**accuracy 三态**：认同，且比我上一轮给的 Q4 约定更准确。模型读的是页面上「答对 109/135 ≈ 81%」这种**页面级总正确率**，本地拿残缺模块重算反而会算偏。修复后 81% / 56% / 75% 全部对上，这就是最硬的证据。

## 三、一个遗留边界，建议再改一行（P2，非阻塞）

### 现象

当 `total_questions` 为 `null`、但模块有数据时：

- 代码会用「模块题量求和」回填 `total_questions`（第 180–181 行）
- 但 accuracy 走的是 else 分支，**保留模型的值**（第 171–177 行）

此时确认卡可能显示：总题量 40、正确率 90%，而逐模块行加起来只有 50% —— 用户一眼能看出矛盾，且这个矛盾会归因到前端。

### 建议改法

```js
// 现状（第 169 行）
} else if (isNum(declared) && sumQuestions === declared) {

// 建议
} else if (declared === null || sumQuestions === declared) {
```

逻辑变成：**模块齐全，或压根没有总题量（此时总题量本来就由模块求和得来）** → 本地重算；只有**明确对不上**（截图只露出部分模块）才信模型。

这样 `total_questions` 与 `accuracy` 永远来自同一套数据，确认卡上不会自相矛盾。
