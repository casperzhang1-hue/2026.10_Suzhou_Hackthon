## 一、背景与目标

### 1.1 背景

**督学这件事，被行业做成了表演。**

公考备考市场只服务「考前」：卖课、押题、打卡群、督学班。但督学的执行方式是错的——打卡群里互相点赞，断签的人悄悄退群；押金班用扣钱制造压迫；机构在出分日集体消失。

结果是：**真正需要被管住的人，一个都没被管住**，因为他们受不了表演。在职备考这群人（不敢让同事知道自己在考公）恰恰既需要外部结构，又拒绝被围观。

同时，考后 180 天的等待期与备考期间的情绪低谷没有人接住。出分日本该是复购决策发生的一天，全行业却在那天缺席。

### 1.2 产品定位（v1.1 修正）

本产品的**本质是督学工具**，但执行逻辑与传统督学相反：

```
底座  督学   目标 → 周计划 → 每日对照 → 缺口 → 补足     ← 用户为什么付费
界面  宠物   把执行状态变成看得见的东西（仓鼠五态）        ← 用户为什么不卸载
纵深  记忆   跨会话对账 + 跨考季继承                      ← 用户为什么不换
```

**卖督学，用陪伴交付，靠记忆锁住。**

一句话定位：**别人用规则督你，我们用关系督你。**
系统不扣分、不排名、不公开，但它等了你一天，并且把缺口摆在你面前。

产品不做内容供给（不讲知识点、不押题、不建题库）。

### 1.3 要解决的问题

| 现状 | 痛点 | 本产品的应对 |
|---|---|---|
| 打卡群督学 | 互相表演，断签即社死 | 私下执行记录，无公开、无排名（FR-18） |
| 押金班 / 连续天数 | 用惩罚与恐惧驱动 | 缺口可视化 + 可清零，**没有「逾期惩罚」这一状态**（8.3） |
| 只有「今天学了多久」 | 没有分母，没有「这周该干什么」 | 目标拆解 → 周计划 → 缺口（FR-15~17） |
| 情绪支持只有「加油」 | 没有「被看见」 | 状态推断 + 宠物形态（FR-06 / FR-08） |

### 1.4 成功指标与口径

| 指标 | 目标 | 口径 | 可见性 |
|---|---|---|---|
| 周计划达成率 | ≥ 60% | 当周完成项 ÷ 当周计划项 | 仅内部 |
| 缺口清零率 | ≥ 70% | 7 天内补足的缺口数 ÷ 缺口总数 | 仅内部 |
| 判定一致率 | ≥ 70% | 系统状态判定与用户每日自评的一致比例；低于此值产品不成立 | 仅内部 |
| 截图通道渗透率 | ≥ 60% | 活跃日中通过截图上传录入数据的天数占比 | 仅内部 |
| 确认卡修正率 | ≤ 15% | 识别确认卡上被修改的字段数 ÷ 展示字段总数 | 仅内部 |
| 干预采纳率 | ≥ 40% | 用户按建议执行（停止学习/调整计划）的次数 ÷ 干预总次数 | 仅内部 |
| D30 留存 | ≥ 45% | 次日留存的用户中第 30 天仍活跃的比例 | 仅内部 |
| 用户可见数字 | — | **仅「欠几次、怎么补」一条** | 对外 |

> **指标纪律（v1.1 新增，硬约束）**：完成率、达成率、连续天数、与同侪的比较**禁止出现在任何用户可见界面**。指标只用于内部看板与迭代决策。
>
> 以上为产品目标值（估算，上线后校准）；**24h 冲刺的验收口径见 13.1，与上表不同**。

## 二、名词与术语

| 术语 | 定义 |
|---|---|
| 陪跑 | 本产品形态：不做内容供给，做督学执行 + 状态推断 + 情绪陪伴 |
| 周计划 | 本周需完成的模块级计划项，通常 ≤6 项 |
| 缺口 | 本周计划中尚未抵扣的项，用户可见的单位是「次」 |
| 顺延 | 缺口在本周内自动延后，不产生额外惩罚 |
| 清零 | 缺口被补足，归档进入记忆 |
| 活力值 vitality | 宠物的生命值，0–100，非对称累积（恶化慢 0.25 / 回暖快 0.40） |
| 羁绊值 bond | 只涨不跌的关系值，解锁帽子/围巾等装饰，断签不收回 |
| 识别确认卡 | 截图识别后将结果展示给用户、允许修改一次再入库的卡片 |
| completion | 当日完成度，0–1，时长达成 60% + 任务达成 40% 加权 |
| 用户四态 | 稳 / 平台期 / 过载 / 崩溃前兆（能量轴 × 进展轴） |
| 宠物五态 | 元气 / 踏实 / 疲惫 / 蔫了 / 休眠（另设第六种非活力态「陪着」，见 13.3） |
| seed 数据 | 预置的 30 天虚拟用户历史数据，用于演示记忆能力 |

## 四、方案对比与选型

### 4.1 数据录入通道

| 方案 | 数据可信度 | 用户摩擦 | 开发成本 | 结论 |
|---|---|---|---|---|
| A. 截图上传为主（多模态一次识别）+ 填报兜底 | 高（带时间戳难伪造） | 低（学习博主本就有截图习惯） | 中 | **✅ 推荐** |
| B. 自主填报（chips + 滑杆）为主 | 低（可虚报，宠物状态失真） | 低 | 低 | 降级为兜底（FR-12） |
| C. OCR + LLM 两段管线 | 中高 | 中 | 高（两套维护） | ❌ 24h 内不可行 |

### 4.2 宠物形象实现

> **变更背景**：需求方提供仓鼠形象参考图（AI 生成，含正面/侧面/背面三视图：米色仓鼠、米色毛线帽、砖红色围巾、棕色背景）。原「小芽 SVG 连续插值」方案与照片级形象冲突，重新比选。

| 方案 | 质感 | 与参考形象一致性 | 开发量 | 24h 可行性 | 结论 |
|---|---|---|---|---|---|
| A. **五态静态图组（AI 生成，风格锁定）+ CSS 微动效** | 照片级 | 高（以参考图为锚） | 小 | ✅ | **✅ 推荐（本期）** |
| B. 矢量化仓鼠 + 参数连续插值 | 中 | 低（会偏离参考图） | 大 | ❌ | 后续版本评估 |
| C. 骨骼动画（Lottie / Rive） | 最佳 | 中 | 很大 | ❌ | ❌ 拒绝 |

**A 方案下「一致性感知」的实现方式调整**：

- 原「连续插值」验收改为：**五态图差异必须肉眼可辨**（姿态 / 帽饰位置 / 眼睛 / 颊囊 / 背景道具）+ 每态 1–2 个 CSS 微动效 + 话术配合
- 三视图用法：正面 = 主界面默认；侧面 = 页面转场过场；背面 = 周报 / 出分日等「它先转身」的叙事页
- **毛线帽与围巾 = 羁绊值的可视化载体**：bond 里程碑解锁新帽子颜色 / 围巾花纹（只涨不跌，断签不收回）

**仓鼠隐喻体系（替代原植物隐喻，写入表达系统）**：

| 原隐喻（小芽） | 新隐喻（仓鼠） | 对应机制 |
|---|---|---|
| 浇水过多烂根 → 疲惫态 | **颊囊塞满**：学太猛，颊囊鼓鼓、帽子歪掉、脚下散落瓜子壳（塞了一堆没消化） | 「敢让你停」 |
| 向光生长 → 元气态 | 挺直坐、帽檐端正、眼神亮、颊囊微鼓 | 元气态 |
| 叶片下垂 → 蔫了态 | 缩成一团、围巾裹紧、耳朵耷拉 | 蔫了态 |
| 种子休眠 | 蜷成毛球，只露出帽子尖 | 休眠态 |
| 年轮 / 枝干 = 成长记录 | **囤积 = 记忆**：它替你囤着每一天（对账时「翻出来给你看」） | 记忆屏叙事 |

> 仓鼠是夜行动物——「你凌晨还在学，它也醒着陪你」，与目标用户（在职备考、深夜学习）天然契合，此点写入文案人格设定。

### 4.3 客户端形态

| 方案 | 触达 | 上线周期 | 结论 |
|---|---|---|---|
| A. H5（手机浏览器 / 微信内打开） | 弱（无服务通知） | 分钟级部署 | **✅ 本期**（演示口径） |
| B. 微信小程序 | 强（服务通知） | 审核 + 域名备案，天级以上 | 后续版本（触发条件：演示通过、进入真实用户测试） |

**演进路径**：H5 验证一致性感知 → 小程序承载推送与留存 → 付费层（陪跑 ¥99/月）。

### 4.4 督学的「后果」由谁承担（v1.1 新增 · 决定产品人格）

| 方案 | 机制 | 压迫感 | 与定位 | 结论 |
|---|---|---|---|---|
| A. 规则后果 | 扣分 / 掉排名 / 押金不退 / 公开断签 | 强 | ✕ 变成表演型督学，撞合规与反焦虑红线 | 拒绝 |
| **B. 关系后果** | **它等了你一天 + 缺口可视化 + 具体补法** | 中 | ✓ 督学成立，且不羞辱 | **✅ 推荐** |
| C. 无后果 | 只记录，不提示缺口 | 无 | ✕ 退化成仪表盘，付费理由消失 | 拒绝 |

**B 的强度靠三件事撑住**（否则就是软绵绵的记录工具）：

1. 缺口**可见**（具体到「资料分析欠 2 次」）
2. 缺口**可清零**（给明确补法，不给压力循环）
3. 缺口**有期限**（本周内可顺延，跨周必须显式「放弃这一次」，不能悄悄滚）

> **诚实声明**：关系驱动的督学，效力弱于规则驱动（打卡群的压迫感是真的）。产品不宣称「比打卡群更能管住你」；它服务的是**拒绝表演、但仍需要外部结构的人**。

## 六、功能需求

> 编号 FR-xx；验收标准 Given / When / Then；「必须」= shall。

### FR-01 截图上传（必须）

- 描述：用户点击「贴一张今天的学习截图」，从相册选择或拍照上传一张图片。
- 规则：仅支持单张；JPG / PNG；≤10MB；上传中显示进度态。
- 验收：
  - Given 用户在首页，When 点击上传并选择一张截图，Then 2 秒内进入识别等待态（不白屏，仓鼠眨眼动效）。
  - Given 用户取消选择，When 返回，Then 停留在首页，无异常提示。

### FR-02 截图识别（必须 · AI 能力）

- 描述：多模态模型一次调用，图片 → 结构化 JSON。禁止 OCR + 二次抽取两段管线。
- 输出契约（必填字段）：

```json
{
  "app": "粉笔 | 番茄ToDo | 其他",
  "date": "YYYY-MM-DD",
  "module": "言语 | 资料分析 | 判断推理 | 常识 | 申论 | 未知",
  "questions": 0,
  "correct": 0,
  "minutes": 0,
  "confidence": 0.0
}
```

- 规则：`correct ≤ questions`，超出时置信度降级；识别失败不得抛错给用户（走 FR-12 降级）。
- 验收：
  - Given 6 张真实截图测试集，When 批量识别，Then ≥5 张输出合法 JSON。
  - Given 一张无关图片（如自拍），When 识别，Then 返回 `confidence < 0.5` 且进入降级，不报错。

### FR-03 识别校验（必须）

- 规则四条：① 时间一致性（截图时间与当日偏差 ≤36h）；② 数值合理性（correct ≤ questions，minutes ≤ 600）；③ 感知 hash 去重；④ 模块名归一。
- 验收：Given 一张 3 天前的旧截图，When 上传，Then 确认卡顶部提示「这是 X 天前的记录」，默认记到截图当日。

### FR-04 识别确认卡（必须）

- 描述：识别结果以 4 个可编辑字段展示（模块 / 题量 / 正确数 / 时长），用户确认或修改一次后入库。
- 验收：
  - Given 识别结果展示，When 用户修改任一字段并点「没问题」，Then 以修改后的值入库，字段标记 `edited=true`。
  - Given 连续 5 次零修正，When 再次识别，Then 提供「自动确认」开关（可以，非必须）。

### FR-05 完成度计算（必须）

- 规则：`completion = 0.6 × min(minutes / 目标时长, 1.2) + 0.4 × min(题量达成率, 1.2)`
- 防伪锚：与被动在线时长冲突时取保守值 `min(识别值, 在线分钟 × 1.2)`；不提示、不戳穿。

### FR-06 用户状态判定（必须）

双轴四象限：能量轴（作息规律性 / 深夜占比 / 情绪）× 进展轴（正确率趋势 / 连续错题）。

| 精力 | 进展 | 判定 | 干预动作 |
|---|---|---|---|
| 高 | 高 | 稳 | 不打扰 |
| 高 | 低 | 平台期 | 建议换方法 |
| 低 | 高 | **过载** | **「今天别学了，去睡」**（核心差异化判定） |
| 低 | 低 | 崩溃前兆 | 只安抚，不布置任务 |

- 验收：Given 精力低 + 进展高，When 计算，Then 判定「过载」并触发劝停话术（FR-09）。

### FR-07 活力值更新（必须 · 方向不可更改）

```
completion < 0.5 :  vitality = 0.75 × vitality + 0.25 × completion×100   （恶化慢）
completion ≥ 0.5 :  vitality = 0.60 × vitality + 0.40 × completion×100   （回暖快）
```

- 规则：休眠态（断签 ≥7 天）vitality 冻结在 25 不再下跌；bond 只涨不跌。
- 验收：
  - Given vitality=80、断签一天（completion=0），When 更新，Then vitality=60（只掉 25%）。
  - Given vitality=60、completion=1.0 回归日，When 更新，Then vitality=76（立刻回暖 40%）。

> v1.1 补充：缓冲的是**惩罚**，不是**反馈**。活力值可以不惩罚用户，但缺口必须如实显示——两者不矛盾。

### FR-08 宠物形态展示（必须）

- 五态映射：元气 ≥78 / 踏实 55–78 / 疲惫（过载判定日）/ 蔫了 30–55 / 休眠（断签 ≥7 天）。

| 态 | 视觉要点 | 微动效 |
|---|---|---|
| 元气 | 帽檐端正、眼神亮、颊囊微鼓、光点 | 呼吸起伏 2s 循环 |
| 踏实 | 标准坐姿 | 呼吸起伏 |
| 疲惫 | **颊囊鼓胀、帽子歪掉、脚下瓜子壳散落、眼半闭** | 慢速眨眼 |
| 蔫了 | 缩团、围巾裹紧、耳朵耷拉 | 偶尔耳朵抖 |
| 休眠 | 蜷成毛球、露帽尖 | 无（静止即表达） |

- 验收：
  - Given 五态图，When 依次切换，Then 每两态差异**肉眼立辨**。
  - Given 参考图三视图，When 出场 / 转场 / 周报，Then 分别使用正面 / 侧面 / 背面。

### FR-09 表达系统（必须）

- 12 条模板话术（四态 × 3）。铁律：主语必须是「我」；禁用词库（加油 / 你一定行 / 坚持就是胜利 / 别放弃 / 你怎么又）；能给数字就给数字。
- 校验：含禁用词或主语为「你」的句子不展示，取下一条。
- 验收：Given 任一态触发，When 输出话术，Then 通过禁用词与主语双重校验。

### FR-10 记忆屏（必须，seed 驱动）

- 展示 3 条历史引用，其中 ≥1 条为冲突对账：「你 41 天前说资料分析一定能拿下。这周它是 48%。你当时少算了什么？」
- 验收：Given seed 已灌库，When 打开记忆屏，Then 3 条引用的时间 / 内容 / 数字与 seed 完全一致（**自洽是硬验收**）。

### FR-11 出分日屏（必须）

- 首字是「我在」，不出现分数、不祝贺、不安慰、不推销；背景使用仓鼠背面视图（「它先转身等你」）。
- 验收：Given 系统日期进入出分日模式，When 用户打开，Then 首页被整体替换，且不包含任何分数询问或课程推广元素。

### FR-12 降级链（必须）

截图识别失败 → chips 兜底（模块多选 + 题量四档 + 感受三档）→ 仍无数据 → 仅用被动信号计算，置信度标记低。**任何一步不得卡死用户。**

### 6.B 督学闭环（v1.1 新增 · 产品底座）

> 编号续接。业务顺序上这一段是产品的骨架：**没有分母，就没有完成度**。v1.0 只有「今天怎么样」，缺少「这周该干什么、欠了多少」。

### FR-15 目标设定（必须）

- 描述：首次进入时设定考期、目标分、各模块当前水平（自评即可）。
- 规则：考期必填（用于倒计时与出分日触发）；目标分与模块水平可跳过后补；**不做初始测评**（避免一上来就是考试感）。
- 验收：Given 新用户首次进入，When 只填了考期，Then 允许继续，且今日屏不显示缺口（无分母时不产生欠账）。

### FR-16 周计划生成（必须）

- 描述：按「距考期周数 × 模块权重 × 差距分」生成当周计划项（模块级，不拆到知识点）。
- 规则：模板优先（资料分析 / 言语 / 判断 / 常识 / 申论 五模块标准配比），用户可改；**AI 只出建议，不自动写入**（可解释、可控）。
- 验收：Given 距考期 8 周、目标分 70、当前 58，When 生成周计划，Then 输出 ≤6 个计划项，且每项可被用户修改或删除。

### FR-17 每日对照（必须）

- 描述：当日录入后，把实际完成映射到本周计划项，计算缺口。
- 规则：一次录入最多抵扣一个计划项；**未录入的日子标记「未记录」而非「未完成」**（不惩罚没打开 App 的日子）。
- 验收：Given 本周计划 5 项、已记录 2 天共完成 2 项，When 打开今日屏，Then 显示「本周欠 3 次」，而不是完成率百分比。

### FR-18 缺口呈现（必须 · 三条硬约束）

1. **上限 3 条**：超过只显示最重要的 1 条（按距考期权重排序）。
2. **可清零**：每条缺口必须给出具体补法（「资料分析欠 2 次，明天做 1 套就平」）。
3. **有期限**：本周内可顺延（不产生额外惩罚）；**跨周必须显式「放弃这一次」**，不得悄悄滚入下周。

- 验收：
  - Given 用户点了「今天别学了」，When 次日查看，Then 缺口顺延到本周内，无额外欠账、无指责性文案。
  - Given 某缺口跨周未补，When 用户打开，Then 弹出一次「这周没补上，先放弃还是挪到下周」，用户选择后才继续。

### FR-19 缺口 → 干预联动（必须）

- 规则：缺口 ≥3 且精力低 → **不催补，改为「这周先砍掉一项」**（减负而非加压）；缺口清零 → 宠物元气态 + 一句具体的话（「这周清了，睡了」）。
- 验收：Given 缺口 3 条 + 精力低，When 生成干预，Then 输出减负建议而非追加任务。

> **指标纪律**：完成率、达成率、连续天数只进内部看板，禁止出现在任何用户可见界面。用户可见的唯一数字是「欠几次、怎么补」。

## 八、业务流程与状态流转

### 8.1 主流程（五步动线）

```
上传截图 → [识别] → 确认卡 → [入库+计算] → 宠物形态+话术（含缺口一行） → 记忆屏 → 出分日屏
              ↓失败                    ↓
           chips 兜底(FR-12)        正常展示
```

### 8.2 宠物状态机

| 当前态 | 触发事件 | 迁移到 |
|---|---|---|
| 任意 | 断签 ≥7 天 | 休眠（vitality 冻结 25） |
| 休眠 | 用户回归当日任意录入 | 蔫了（首句「你回来了」，绝口不提离开多久） |
| 踏实 | completion<0.5 累积 | 蔫了（vitality 跌破 55） |
| 踏实 / 元气 | 过载判定 | **疲惫**（不是开心，是劝停） |
| 蔫了 | completion≥0.5 | 踏实（vitality 回涨 40%） |
| 任意 | vitality ≥78 且无过载 | 元气 |

> ⚠️ 用户四态与宠物五态**不是一对一映射**：用户今天「过载」但宠物可能还在「踏实」（历史活力未耗尽）。错位是设计（缓冲垫），禁止实现成严格镜像。

### 8.3 缺口状态机（v1.1 新增）

| 当前状态 | 触发事件 | 迁移到 | 允许操作 |
|---|---|---|---|
| — | 当日录入后未抵扣计划项 | 待补 | 补足 / 顺延 |
| 待补 | 用户补足 | **已清零**（归档，写入记忆） | — |
| 待补 | 周末到期未补 | 待确认 | 弹一次选择 |
| 待确认 | 用户选「挪到下周」 | 待补（**仅可顺延 1 次，不得二次顺延**） | — |
| 待确认 | 用户选「放弃这一次」 | **已放弃**（记录，不指责，写入记忆） | — |
| 待确认 | 用户跳过未选 | 待确认（保持，不升级为惩罚，不重复弹） | — |

> 设计约束：缺口只有「待补 / 已清零 / 已放弃」三个终局，**没有「逾期惩罚」这个状态**。这是与传统督学最本质的差别。

## 十五、附录

### 15.1 AI 功能专项契约（精要）

- **任务定义**：多模态模型在用户上传学习截图时完成字段结构化抽取（草稿级，经确认卡人工确认后生效）；成本 ≈¥0.005/次。
- **输入契约**：单张截图；缺字段时输出 `confidence<0.5` 而非编造；截图时间与历史冲突时以截图时间为准。
- **输出契约**：FR-02 JSON Schema，必填字段缺失即视为失败；禁止用自然语言替代结构化字段。
- **质量标准**：6 张测试集 ≥5 张合法 JSON；验收样本覆盖 常规 / 无关图 / 旧图 / 数值颠倒 四类。
- **异常降级**：失败不弹错，降级 chips（FR-12）；人工接管点 = 确认卡。
- **行为约束三层**：
  - Always do：结构化抽取、按模板出话术、按规则算状态
  - Ask first：数据入库、改写周计划、变更缺口状态
  - Never do：无可靠来源时编造字段、修改用户未确认的数据、向用户展示完成率与同侪对比、在出分日 72 小时内主动推送
- **反馈闭环**：`edited_fields` 逐字段记录；每条结果关联 prompt 版本号，可复现。
