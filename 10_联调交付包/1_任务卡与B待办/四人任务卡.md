# 四人任务卡 · 24 小时冲刺

> 起点 2026-10-30 22:16 ｜ 截止 2026-10-31 22:16 ｜ **交付形式：6 分钟现场路演**

---

## 先说清楚：明天要交付的到底是什么

不是一个"完整的产品"，是**一场不会翻车的 6 分钟演示**。

评委只会记住三件事：

1. 一株小芽，因为用户今天学太多，**它反而蔫了**，并且说"今天别学了"
2. 它记得用户 **41 天前**说过的一句话，并且敢拿出来对账
3. 出分那天，所有机构都消失了，**它还在**

这三件事必须在同一场演示里、连续地、不出错地发生。**其余所有功能都是配角。**

---

## 五步动线（全队只有这一条主线）

```
① 手机上传一张真实学习截图
        ↓  A 做界面    C 做识别
② 识别结果确认卡（4 个数字，可改）
        ↓  A 做卡片    C 提供数据
③ 点「没问题」→ 小芽形态当场变化 + 它说一句话
        ↓  A 做宠物    B 算状态    C 写话术
④ 翻到记忆屏：「你 41 天前说资料分析一定能拿下，这周 48%」
        ↓  D 造数据    B 存取    C 造句
⑤ 翻到出分日屏：「我在」
        ↓  A 做页面    D 写文案
```

**①②③ 是命门。** ①②③ 断了，整个演示就没了。④⑤ 可以用预置数据撑。

## A · 前端 + 视觉

### 你是干什么的
用户打开手机看到的**所有东西**都是你做的。你最重要的工作不是"画页面"，是**让那株小芽看起来真的在反映他的状态**。

### 你要做的功能

**1. 小芽组件（最高优先级，先做这个）**

五个状态：

| 状态 | 什么时候 | 长什么样 |
|---|---|---|
| 元气 | 学得好、睡得够 | 叶片展开、有光点、腮红明显 |
| 踏实 | 一般般、但没断 | 稳稳站着，叶片微抬 |
| **疲惫** | **学太多、熬夜了** | **浮肿、黑眼圈、脚下一滩水** |
| 蔫了 | 断签了 | 叶片下垂、颜色发灰 |
| 休眠 | 断签 7 天以上 | 缩成一颗种子 |

**关键要求（这条决定产品成败）：**

❌ 错：做 5 张图，按状态切换 → 用户觉得"今天换了个皮"
✅ 对：做**一套 SVG**，体型、颜色饱和度、眼睛开合、叶片角度、腮红、光点，全部随一个 `0–100` 的数字**连续变化**

验收标准：在一个滑杆上从 0 拖到 100，**肉眼能看出它是慢慢变的，中间没有"啪"的一下**。

**2. 五块页面**

- 上传屏（一个"贴一张截图"的大按钮）
- 识别确认卡（4 个数字，每个都能改）
- 今日屏（小芽 + 一句话，**小芽必须占屏幕最大的位置**）
- 记忆屏（3 条"它记得的事"）
- 出分日屏（一句"我在"）

**3. 识别的等待态**
识别要 2–3 秒，这段时间**不能白屏**。放个"正在看你的截图"的加载状态，让小芽先眨个眼。

### 你要交的东西

| 文件/成果 | 什么时候 | 长什么样 |
|---|---|---|
| `Pet` 组件 + **滑杆调试页** | **02:00** | 打开一个网页，拖滑杆，小芽连续变形 |
| 五块页面（数据全写死） | 04:00 | 能来回点，不用真实数据 |
| 接真数据 | 12:00 | 上传截图后，小芽真的变了 |
| 全部走通 | 16:00 | 五步动线一遍过（丑没关系） |
| 视觉统一 | 18:00 | 字体、间距、配色一致，没有毛边 |

### 你做砸了会怎样
小芽不好看、变化不明显 → 整个产品的情绪价值不存在 → 路演现场没有"哇"的那一下 → 只剩一个普通的打卡工具。

### 你不要做的事
登录页、设置页、排行榜、社交分享、多余动画、暗色模式。**一个都别做。**

## B · 后端 + 状态引擎

### 你是干什么的
用户传了截图，系统要判断"他今天什么状态""小芽该长什么样"。**这个判断就是你写的。**

而且有一条硬要求：**同样的数据，今天算和明天算，结果必须一模一样。** 不能今天说"过载"，明天改口说"稳"。

### 你要做的功能

**1. 一个判断函数 `computeDailyState()`**

输入（今天的信号）：
- 学了多久、做了几题、对了多少
- 几点开始、几点结束、有没有熬到凌晨
- 断签了几天
- 昨天的小芽活力值

输出（今天的状态）：
- 完成度 `completion`（0–1）
- 精力分 `energy`（0–100）
- 进展分 `progress`（0–100）
- 用户状态：**稳 / 平台期 / 过载 / 崩溃前兆**（四选一）
- 活力值 `vitality`（0–100）
- 小芽形态：五选一

**2. 非对称算法（这是灵魂，方向不能改）**

```
表现差（完成度 < 0.5）：活力值只往下跌一点点  →  只掉 25%
表现好（完成度 ≥ 0.5）：活力值立刻往上跳      →  立刻涨 40%
```

为什么：用户断签一天，小芽只是"有点蔫"，**不能崩**。用户回来第一天，立刻回暖。
如果做成严格镜像，用户会内疚 → 更不敢打开 → 断签更久 → 卸载。**宠物是缓冲垫，不是镜子。**

**3. 两张判断表**

| 精力 | 进展 | 判定 | 该说什么 |
|---|---|---|---|
| 高 | 高 | 稳 | 不打扰 |
| 高 | 低 | 平台期 | 换个方法 |
| **低** | **高** | **过载** | **"今天别学了，去睡"** ← 全场最值钱的一格 |
| 低 | 低 | 崩溃前兆 | 只安抚，不布置任务 |

**4. 数据库 + 接口**

- 存：用户、截图记录、每日状态、记忆
- 三个接口：传截图 → 存；查今天 → 返回状态；查记忆 → 返回历史引用

**5. 灌 seed 数据**
D 会造一份 30 天的假数据，你负责灌进库、并能查出来。

### 你要交的东西

| 文件/成果 | 什么时候 | 长什么样 |
|---|---|---|
| **两份数据格式（schema）** | **23:00** | 发到群里，A 和 C 照着这个写 |
| `computeDailyState` + 6 个测试用例 | 04:00 | 跑一遍全绿：正常/断签1天/断签7天/过载/回归/新用户 |
| 3 个接口 | 12:00 | 前端能直接调 |
| seed 灌库 + 能查 | 14:00 | 记忆屏能翻出 3 条历史 |

⚠️ **23:00 的 schema 是全队唯一的前置依赖。** 你不发，A 和 C 都在瞎猜，全队等着你。

### 你做砸了会怎样
算错了 → 小芽的反应不合理（用户明明很拼，它却元气满满）→ "它懂我"这件事不成立 → 产品退化成记工时的工具。

### 你不要做的事
- ❌ 不要用大模型判断状态（又贵又慢又不可解释，还会今天一个答案明天一个）
- ❌ 不要做多用户、并发、权限、缓存
- ❌ 不要重构，能用就行

## C · AI 链路

### 你是干什么的
用户传一张粉笔/番茄 ToDo 的截图，你要让机器**看懂里面写了什么**——做了几道题、对了多少、什么时候做的。

**这是整个产品"真实"的唯一来源。** 你搞不定，产品就退回到"用户自己填数字"，那所有防伪设计全部作废。

### 你要做的功能

**1. 截图 → 结构化数据（一次调用）**

一张图进去，出来一段 JSON：

```json
{
  "app": "粉笔",
  "date": "2026-10-30",
  "module": "资料分析",
  "questions": 30,
  "correct": 21,
  "minutes": 52
}
```

⚠️ **重要技术决定：用多模态模型一次调用直接出 JSON，不要做"OCR → 再抽取"两段。**
两段管线工程量翻倍，24 小时里做不完，而且效果通常更差。

**2. 测试集（6 张真实截图）**

自己截、找朋友要、网上找——**必须有真实的**，不能全是自己 P 的。
验收：6 张里至少 **5 张**能出合法 JSON。

**3. 认不出来时不能卡死**

认不出 → 降级成"手动选一下这几项"，页面继续走。
**用户永远不应该看到一个白屏或者报错弹窗。** 这是你的核心 KPI。

**4. 小芽说的话（12 条）**

四个状态各 3 条。三条铁律：

| 铁律 | ✕ 错 | ✓ 对 |
|---|---|---|
| **主语必须是"我"** | "你今天又没打卡" | **"我今天没什么精神"** |
| **禁用鼓励词** | 加油、你一定行、坚持就是胜利、别放弃 | — |
| **能给数字就给数字** | "你最近状态不好" | "你这三天都到了一点" |

**优先用模板池，不要每次都调模型。** 模板快、稳、免费、不会飘。模型只在模板都对不上时才用。

**5. 记忆对账那句话**
"你 41 天前说资料分析一定能拿下。这周它是 48%。**你当时少算了什么？**"
最后那个问句是关键——它把评价权交回用户，不是审判。

### 你要交的东西

| 文件/成果 | 什么时候 | 长什么样 |
|---|---|---|
| 模型调通 hello | 23:00 | 传一张图能出字 |
| prompt v2 + 6 张测试集 | 02:00 | 跑批脚本输出"5/6 通过" |
| 前端可调用 | 12:00 | A 传图能拿到 JSON |
| `phrases.json` 12 条 | 16:00 | 四个状态各 3 条，标注对应状态 |

### 你做砸了会怎样
识别不准 → 数据不可信 → 小芽乱变 → **"以截图为准"这个核心卖点当场作废**，产品回到红海。

### 你不要做的事
- ❌ 不要做 OCR 两段管线
- ❌ 不要训练/微调模型
- ❌ 不要追求 100% 准确（有确认卡兜底，70% 就够用）
- ❌ 不要做多语言、表格、手写体

## D · 产品 + 路演（你，张宇辰）

### 你是干什么的
你不一定要写代码。你决定两件事：**这 24 小时做出来的东西，明天怎么在 6 分钟里让人记住**；以及**那套假数据要真到什么程度**。

### 你要做的功能

**1. 造 30 天假数据（最被低估的活）**

造一个虚拟用户：在职，考公，目标行测 70+。

**关键是它必须有故事线，不能是随机数：**

| 天 | 发生了什么 |
|---|---|
| D1–D7 | 正常学，小芽从种子长成小苗 |
| **D8** | 断签（加班）→ 小芽有点蔫，但只掉 25% |
| D9 | 回来 → 立刻回暖（这就是非对称机制的证据） |
| **D15** | 崩了一次，凌晨 2 点还在学 → 小芽「疲惫」，说"今天别学了" |
| D16–D21 | 恢复，稳步上升 |
| **D22** | 说了一句话：**"资料分析我一定能拿下"** ← 记忆屏要引用的就是这条 |
| D23–D29 | 资料分析正确率反而下滑到 48% |
| **D30** | 今天，做 demo 的这一天 |

**必须自洽**：记忆屏说"41 天前"、说"这周 48%"，seed 里就得真有那条记录、真算得出 48%。**评委最爱抓的就是"你这数据是编的吧"，唯一的防法是编得严丝合缝。**

**2. 六分钟逐字稿**

不是大纲，是**每一句都写出来**，包括"这里我停一下，让他看屏幕"。

时间分配：

| 时长 | 讲什么 |
|---|---|
| 0:00–0:45 | 行业只服务考前，没人管考后那 180 天 |
| **0:45–3:15** | **现场 demo**（五步动线，你亲自操作手机） |
| 3:15–4:15 | 记忆屏：它记得，而且敢说 |
| 4:15–5:00 | 出分日：别人都走了它还在 |
| 5:00–6:00 | 壁垒 + 账（¥15–31/考季 vs ¥99/月） |

**3. pitch 材料**：不超过 8 页。多了没人看。

**4. 兜底录屏 90 秒**：18:00 前录完，干净版。现场如果网络挂了，直接放。

### 你要交的东西

| 文件/成果 | 什么时候 | 长什么样 |
|---|---|---|
| `seed.json` 30 天数据 | 24:00 | 交给 B 灌库，字段对齐 B 的 schema |
| `路演脚本.md` 逐字稿 | 04:00 | 能照着念 |
| 按实际跑通情况改 | 12:00 | 演示到哪步，话就说到哪步 |
| `pitch.pdf` ≤8 页 | 18:00 | — |
| `fallback.mp4` 90 秒 | 18:00 | 断网也能演 |

### 你不要做的事
- ❌ 不要在 16:00 之后提新功能（你自己定的规矩，你自己先守）
- ❌ 不要在最后两小时改叙事结构
- ❌ 不要把 demo 讲成功能罗列（观众记不住超过 3 个功能）
